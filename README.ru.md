# EXX

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.md) [![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

EXX переводит процедуры с высокоуровневого ассемблера в исходный код на ассемблере Z80.
Каждая процедура объявляет свой регистровый интерфейс (ABI). Это позволяет
заменить процедуру в банке ПЗУ или собрать объектный модуль для библиотеки
z88dk, сохранив существующий порядок вызова. Транслятору нужен Python 3.10
или новее. Все зависимости входят в стандартную библиотеку.

```text
extern video_stack_safe(window → B, session: VID_SESSION → IX)
    → (CF, A) clobbers(C, HL, F)

check_window(window → B, session: VID_SESSION → IX)
    → (CF, A) clobbers(C, HL, F) {
    (CF, A) = video_stack_safe(window, session)
    if (CF) return (CF, A)
    return (0, 1)
}
```

```asm
check_window:
    call video_stack_safe
    ret c
    xor a
    inc a
    ret
```

Аргументы уже находятся в B и IX. Вызов и проверка ошибки превращаются
в `call video_stack_safe` и `ret c`. При успехе выполняются `xor a`,
`inc a` и `ret`. Вызывающая процедура получает A = 1 и сброшенный флаг переноса.

## Как читать примеры

Под каждым примером EXX приведён вывод таргета `asm`, если явно не указан другой таргет.
Для фрагментов тела процедуры показаны соответствующие инструкции и метки переходов.
Метка входа в окружающую процедуру и её неявный завершающий `ret` опущены.
В этих фрагментах `session` — указатель на `VID_SESSION` в IX, а `packet` — указатель на `PACKET` в IY.

## Сборка модуля

### Фрагмент для включения в ASM

Таргет `asm` выдаёт символический ASM для Z80. Подключите файл в нужном банке ПЗУ через
`INCLUDE "cursor.asm"`. Адрес размещения задаёт основной ассемблерный файл.

```sh
./exx --target asm examples/sdk_console_cursor.exx -o cursor.asm
```

Обе процедуры курсора теперь можно подключить одним файлом. [Полученный cursor.asm](tests/golden/asm/sdk_console_cursor.asm)

### Модуль для линковки

Таргет `z80asm` оформляет те же инструкции директивами `SECTION`, `PUBLIC` и `EXTERN` для
`z88dk-z80asm`. Объектный файл можно слинковать с другими ASM-модулями. Для вызова из C
потребуется совместимое соглашение о вызовах или адаптер на ASM.

```sh
./exx --target z80asm --section code_clib examples/sdk_console_cursor.exx -o cursor.asm
z88dk-z80asm cursor.asm
```

Полученный модуль начинается с этих директив.

```asm
    SECTION code_clib
    PUBLIC zx__console_newline
    PUBLIC zx__console_advance
```

### Выбор процессора

Процессор задаётся через `--platform`. По умолчанию EXX выбирает первую платформу таргета. Без
`-o` ассемблерный текст выводится в stdout.

```sh
./exx --platform z80 --target asm examples/advance_block.exx
```

В выводе видны процедура и вызывающий её код. [Полученный advance_block.asm](tests/golden/asm/advance_block.asm)

### Подключение файлов ассемблера

Опция `--include` подключает определения раскладок и констант перед сгенерированными процедурами.

```sh
./exx --target asm --include layout.inc examples/buffer.exx -o buffer.asm
```

```asm
    INCLUDE "layout.inc"
```

### Ассемблер на уровне файла

Блок `asm { … }` позволяет размещать таблицы, метки, макросы и директивы между процедурами
EXX. Оба таргета выводят блоки в исходном порядке после заголовка модуля. Отступы, имена
символов и комментарии внутри блока передаются ассемблеру в исходном написании. Для условной
сборки используйте синтаксис выбранного ассемблера. Собственного препроцессора
`#define` и `#ifdef` у EXX нет.

```text
asm {
hex_digits:
    defb "0123456789ABCDEF"
}
```

```asm
hex_digits:
    defb "0123456789ABCDEF"
```

### Встроенный ассемблер с регистровым контрактом

Внутри процедуры в скобках указываются читаемые регистры, после стрелки — результаты,
в `clobbers` — остальные изменяемые регистры и флаги. В контракте допустимы алиасы,
в ассемблерном тексте используются физические имена регистров. Пропущенный список
считается пустым. Например, `asm { nop }` сохраняет все регистры и флаги. EXX проверяет
окружающий код по объявленному контракту. Автор вставки отвечает за его соблюдение,
восстановление стека и переход управления к следующему оператору EXX. Внешние символы,
которые используются только внутри вставки, объявляются директивами ассемблера.

```text
invert(value → A) → A clobbers(HF, N) {
    asm(value) → A clobbers(HF, N) {
        cpl
    }
    return value
}
```

```asm
invert:
        cpl
    ret
```

### Общие объявления ABI

Передайте один файл объявлений вызывающему и вызываемому модулям. EXX сверит входные регистры и
типы, порядок результатов и `clobbers`. Для нескольких файлов повторите `--abi`. Реализация на
ASM должна соблюдать объявленный контракт.

```sh
./exx --target z80asm --abi video.abi video.exx -o video.asm
./exx --target z80asm --abi video.abi caller.exx -o caller.asm
```

Например, в `video.abi` объявлена процедура `extern read_page(page → E) → A`.
Если в `video.exx` записать `read_page(page → E) → A { return page }`, а в `caller.exx` —
`fetch_page(page → E) → A { return read_page(page) }`, оба модуля будут ссылаться на одно имя.

```asm
; video.asm
    SECTION code_user
    PUBLIC read_page

read_page:
    ld a, e
    ret
```

```asm
; caller.asm
    SECTION code_user
    PUBLIC fetch_page
    EXTERN read_page

fetch_page:
    jp read_page
```

### Интеграция с Make

Подключите `exx.mk`, чтобы Make пересобирал ASM при изменении исходника, транслятора или общего
файла из `EXX_ABI`.

```make
include path/to/exx/exx.mk
EXX_TARGET := asm
EXX_ABI := video.abi

build/%.asm: src/%.exx $(EXX_TOOL_DEPS)
	$(exx_compile)
```

## Процедуры и регистры

### Комментарии исходника

Оба таргета переносят комментарии `//` и `/* … */` в ASM отдельными строками с `;`.
Описание процедуры появляется перед её меткой. Если оператор не даёт инструкций,
комментарий остаётся в исходном порядке рядом с остальным кодом.

```text
// Вернуть номер страницы, переданный вызывающей стороной.
read_page(page → E) → A {
    /* Вызывающая сторона ждёт результат в A. */
    return page
}
```

```asm
; Вернуть номер страницы, переданный вызывающей стороной.
read_page:
    ; Вызывающая сторона ждёт результат в A.
    ld a, e
    ret
```

### Параметры в регистрах

Стрелка связывает имя параметра с физическим регистром. Здесь при входе `page` уже находится в E.

```text
read_page(page → E) → A { return page }
```

```asm
read_page:
    ld a, e
    ret
```

### Локальные имена регистров

Локальная привязка даёт имя регистру или сразу нескольким регистрам. Чтение по имени возвращает
текущее содержимое регистра.

```text
(cursor, remaining) → (HL, DE)
cursor += 1
```

```asm
    inc hl
```

### Проверка аргументов при вызове

EXX проверяет количество и расположение аргументов. В этом примере вызывающая процедура явно
переносит значение из D в требуемый E.

```text
extern select_page(page → E)
select_from_d(page → D) clobbers(E) {
    E = page
    select_page(E)
}
```

```asm
select_from_d:
    ld e, d
    call select_page
    ret
```

### Несколько возвращаемых значений

Значения возвращаются в порядке сигнатуры. Здесь CF сохраняет своё значение, а A получает 5.
Если для перестановки значений нужен временный регистр, пересылки указываются явно.

```text
status(carry → CF) → (CF, A) { return (carry, 5) }
```

```asm
status:
    ld a, 5
    ret
```

### Получение результатов вызова

Перечислите все регистры результата в порядке объявления. Если результат не нужен, запишите
вызов отдельным оператором. Условный смысл результата, например код ошибки в A при CF=1, укажите
в описании процедуры.

```text
extern query() → (A, HL, DE)
inspect() → HL clobbers(A, DE) {
    (A, HL, DE) = query()
    return HL
}
```

```asm
inspect:
    call query
    ret
```

### Хвостовые вызовы

Возврат вызова с совместимыми выходными регистрами превращается в переход. Целевая процедура
должна быть доступна при текущем отображении памяти.

```text
extern read_byte() → A
fetch() → A { return read_byte() }
```

```asm
fetch:
    jp read_byte
```

### Объявление изменяемых регистров

`clobbers` разрешает изменения, видимые вызывающему коду. Объявленный результат доступен и
тогда, когда его регистр входит в `clobbers`. F охватывает шесть документированных флагов. Пары
AF, BC, DE и HL перекрываются со своими частями.

```text
extern probe() → (CF, A) clobbers(HL, F)
```

Само объявление `extern` не порождает инструкций. При вызове `probe` из модуля для `z80asm` в его заголовке появится `EXTERN probe`.

### Проверка доступности значений

Для чтения регистр должен содержать определённое значение на каждом пути, в том числе после
перехода на новую итерацию. Здесь после `work()` нужно заново определить D, прежде чем вернуть
DE.

```text
extern work() clobbers(D)
reset_high(word → DE) → DE {
    work()
    D = 0
    return word
}
```

```asm
reset_high:
    call work
    ld d, 0
    ret
```

## Условия и циклы

### Проверка флагов

`if (CF)` и `if (Z)` читают текущий флаг. Сразу после вызова такая проверка использует флаг,
который вернула процедура.

```text
(CF, A) = probe()
if (CF) return (CF, A)
return (0, 1)
```

```asm
    call probe
    ret c
    xor a
    inc a
    ret
```

### Проверка аккумулятора

`if (A)` проверяет, что байт ненулевой, а `if (!A)` — что он равен нулю. В обоих случаях
выполняется `or a`, которая обновляет F.

```text
if (!A) return A
return 1
```

```asm
    or a
    ret z
    ld a, 1
    ret
```

### Беззнаковые сравнения

При сравнении двух байтов один операнд должен находиться в A. Ветка `else` выполняется, если
условие ложно. Сравнение обновляет флаги.

```text
if (A < C) return A
else return C
```

```asm
    cp c
    ret c
    ld a, c
    ret
```

### Присваивание в условии

Заключите присваивание в скобки, чтобы загрузить значение непосредственно в месте проверки.
Регистр назначения можно указать через алиас.

```text
if ((A = session->action) == RST8_VID_PREP_DRAW) return 1
return 0
```

```asm
    ld a, (ix + VID_SESSION.action)
    cp RST8_VID_PREP_DRAW
    jp nz, exx__example_1
    ld a, 1
    ret
exx__example_1:
    ld a, 0
    ret
```

### Сокращённое вычисление условий

`&&` и `||` вычисляют правую часть только при необходимости. Здесь поле загружается в A только
на пути с установленным Z.

```text
if (Z && (A = session->action) == 1) return A
return 0
```

```asm
    jp nz, exx__example_1
    ld a, (ix + VID_SESSION.action)
    cp 1
    ret z
exx__example_1:
    ld a, 0
    ret
```

### Цикл с предусловием

`while` проверяет условие до каждой итерации. При нуле в A этот цикл сразу заканчивается.

```text
while (A) {
    HL += 1
    A -= 1
}
```

```asm
exx__example_1:
    or a
    jp z, exx__example_2
    inc hl
    sub 1
    jp exx__example_1
exx__example_2:
```

### Счётный цикл

`repeat` выполняет тело, затем уменьшает B командой `djnz`, которая сохраняет флаги. При
начальном нуле будет 256 итераций, если тело сохраняет B. Если обратный переход может оказаться
слишком дальним, EXX использует ближнюю метку для `djnz` и абсолютные переходы.
Расстояние через вставку ASM считается неизвестным.

```text
count → B
count = 16
repeat (count) {
    *HL = A
    HL += 1
}
```

```asm
    ld b, 16
exx__example_1:
    ld (hl), a
    inc hl
    djnz exx__example_1
```

### Досрочный выход из цикла

`break` выходит из ближайшего `while` или `repeat`. Здесь при нулевом байте выход происходит до
изменения HL и B.

```text
repeat (B) {
    if (!(A = *HL)) break
    HL += 1
}
```

```asm
exx__example_1:
    ld a, (hl)
    or a
    jp z, exx__example_2
    inc hl
    djnz exx__example_1
exx__example_2:
```

## Память и символы

### Байтовые указатели

`*ptr` обращается к байту по адресу в BC, DE, HL, IX или IY. При адресации через BC или DE байт
передаётся через A. Здесь получаются `ld a,(de)` и `ld (hl),a`.

```text
(src, dst) → (DE, HL)
A = *src
*dst = A
```

```asm
    ld a, (de)
    ld (hl), a
```

### Индексная адресация

Для указателя в IX или IY допустимо постоянное смещение от −128 до 127. Символьное смещение
вычисляет основной ассемблер.

```text
previous(cursor → IX) → A { return cursor[-1] }
```

```asm
previous:
    ld a, (ix - 1)
    ret
```

### Типизированные поля структур

Имя раскладки задаёт префикс смещений и проверяется при передаче указателя по имени, через алиас
или физический регистр. Для загрузки байта ниже таргет `asm` использует `VID_CTX.config`, а
`z80asm` — `VID_CTX_config`. За адрес отвечает вызывающая сторона.

```text
config(ctx: VID_CTX → IY) → A { return ctx->config }
```

```asm
config:
    ld a, (iy + VID_CTX.config)
    ret
```

### 16-битные поля

По умолчанию поле имеет ширину `u8`. При ширине `u16` EXX читает или пишет два байта, начиная с
младшего. Оба смещения должны попадать в диапазон индекса. Слово может находиться в BC, DE или
HL. Можно также записать константу.

```text
field DRV_HEADER.ops: u16
install(h: DRV_HEADER → IY, table → HL) { h->ops = table }
```

```asm
install:
    ld (iy + DRV_HEADER.ops), l
    ld (iy + DRV_HEADER.ops + 1), h
    ret
```

### Адреса внешних данных

Объявите символ данных через `extern data` и возьмите его адрес оператором `&`. Таргет `z80asm`
добавит `EXTERN` для используемых данных.

```text
extern data bs_storage_ops
table_address() → HL { return &bs_storage_ops }
```

```asm
table_address:
    ld hl, bs_storage_ops
    ret
```

### Константы ассемблера

Имена в верхнем регистре и квалифицированные имена смещений передаются в ASM как символы. Их
значения и адреса банков задаёт основной проект.

```text
A = VID_CTX.slot0 ^ VID_CTX.slot1
```

```asm
    ld a, 0 + (VID_CTX.slot0 ^ VID_CTX.slot1)
```

## Арифметика и биты

### Числовые литералы

Доступны десятичная, шестнадцатеричная и двоичная записи. Оба присваивания загружают 128.

```text
A = 0x80
B = 0b10000000
```

```asm
    ld a, 128
    ld b, 128
```

### Арифметика с аккумулятором

Укажите регистр назначения явно. Чтобы сложить B и C, перенесите B в A и прибавьте C. Операторы
разделяются переводом строки или точкой с запятой. Для неподдерживаемой формы EXX указывает
строку исходника.

```text
A = B
A += C
```

```asm
    ld a, b
    add a, c
```

### Арифметика регистровых пар

Указатель можно увеличить или уменьшить непосредственно в регистровой паре. Сложение `HL += DE`
даёт `add hl,de`.

```text
HL += DE
HL -= 1
```

```asm
    add hl, de
    dec hl
```

### Проверка бита

`$` выбирает бит с постоянным номером от 0 до 7. Проверка регистра или индексного поля
использует `bit` и сохраняет CF.

```text
if (packet->status$3) return 1
return 0
```

```asm
    bit 3, (iy + PACKET.status)
    jp z, exx__example_1
    ld a, 1
    ret
exx__example_1:
    ld a, 0
    ret
```

### Запись бита

Присваивание `true` даёт `set`, а `false` — `res`. Обе команды сохраняют F.

```text
packet->status$3 = false
```

```asm
    res 3, (iy + PACKET.status)
```

### Маска AND

`&=` оставляет в A биты, заданные маской. Этот пример даёт `and 127` и обновляет F.

```text
A &= ~(1 << 7)
```

```asm
    and 127
```

### Маска OR

`|=` устанавливает в A указанные маской биты. Здесь получится `or 128` с обновлением F.

```text
A |= 0x80
```

```asm
    or 128
```

### Исключающее ИЛИ

`^=` инвертирует биты по маске. Для операнда в E получится `xor e` с обновлением F.

```text
A ^= E
```

```asm
    xor e
```

### Инверсия байта

`~A` инвертирует все восемь битов командой `cpl`. CF, S, Z и PV сохраняются.

```text
A = ~A
```

```asm
    cpl
```

### Логические сдвиги байта

`<<=` сдвигает влево, а `>>=` — вправо с заполнением нулями. Байтовые сдвиги и вращения
принимают регистр или индексное поле и число шагов от 0 до 255, известное EXX. Каждый шаг
обновляет F. При нуле шагов значение и флаги сохраняются.

```text
B >>= 2
```

```asm
    srl b
    srl b
```

### Арифметический сдвиг вправо

`sra` на каждом шаге заполняет старший бит знаковым. Именованные операции сдвига
и вращения по умолчанию выполняют один шаг.

```text
sra(D, 2)
```

```asm
    sra d
    sra d
```

### Сдвиг слова влево

Сдвиг HL влево на один разряд даёт `add hl,hl`. Команда обновляет CF, HF и N и сохраняет
остальные документированные флаги.

```text
HL <<= 1
```

```asm
    add hl, hl
```

### Циклические вращения

`rlc` вращает байт влево, а `rrc` — вправо. Вытесненный бит попадает на другой конец
байта и одновременно копируется в CF.

```text
rlc(B)
```

```asm
    rlc b
```

### Вращения через перенос

`rl` и `rr` используют CF как дополнительный бит. В этом примере
`sra d` помещает младший бит D в CF, затем `rr e` переносит его в старший бит E.

```text
sra(D)
rr(E)
```

```asm
    sra d
    rr e
```

### Сложение с переносом

`adc` прибавляет к первому операнду второй и входной CF, затем обновляет F. На Z80
доступны формы с A и HL.

```text
adc(HL, DE)
```

```asm
    adc hl, de
```

### Вычитание с заёмом

`sbc` вычитает из первого операнда второй и входной CF, затем обновляет F. Здесь
получится `sbc a,e`.

```text
sbc(A, E)
```

```asm
    sbc a, e
```

## Стек и наборы регистров

### Сохранение регистров на время блока

`keep` сохраняет регистровые пары в порядке перечисления и восстанавливает их в обратном порядке.
Пары можно называть через алиасы. Здесь копирование сохраняет оба указателя, счётчик и AF, занимая восемь байт стека.

```text
copy_bytes(source → HL, destination → DE, count → BC) {
    keep(AF, source, destination, count) {
        ldir(destination, source, count)
    }
}
```

```asm
copy_bytes:
    push af
    push hl
    push de
    push bc
    ldir
    pop bc
    pop de
    pop hl
    pop af
    ret
```

Вложенные блоки восстанавливают регистры начиная с внутреннего. При раннем `return` закрываются все
активные блоки `keep`, а при `break` — только те, из которых выходит переход. Условие проверяется по флагам
до восстановления. Если EXX не может доказать, что восстановление сохранит живой результат или аргумент
хвостового вызова, он укажет на ошибку. Например, чтобы вернуть новое значение A, запишите `return 5`
после `keep(AF)`. Ручные операции со стеком внутри блока должны быть сбалансированы над сохранёнными словами.

### Сохранение в стеке

`push` сохраняет слово, а `pop` загружает его в выбранную пару. EXX отслеживает
инициализированные части слова и после вызова. Здесь процедура сохраняет BC по своему ABI. На
слиянии веток глубина стека должна совпадать, при любом выходе, включая хвостовой переход, —
равняться входной. SP зарезервирован для стека вызовов. При записи через указатели следите за
сохранностью слов на стеке.

```text
extern work() clobbers(BC)
run_preserving_bc() {
    push(BC)
    work()
    pop(BC)
}
```

```asm
run_preserving_bc:
    push bc
    call work
    pop bc
    ret
```

### Обмен регистровых пар

Обмен DE и HL выполняется одной командой. Записи `ex(DE, HL)` и `ex(HL, DE)` дают одинаковый код.

```text
ex(DE, HL)
```

```asm
    ex de, hl
```

### Обмен с вершиной стека

`ex_sp` обменивает HL, IX или IY со словом на вершине стека. Здесь IX получает прежнее
значение BC, затем DE получает прежнее значение IX.

```text
push(BC)
ex_sp(IX)
pop(DE)
```

```asm
    push bc
    ex (sp), ix
    pop de
```

### Теневые регистры

`ex(AF)` даёт `ex af,af'`. Вызов `exx()` обменивает BC, DE и HL с их теневыми парами. В сигнатуре
теневые пары обозначаются `AF_ALT`, `BC_ALT`, `DE_ALT` и `HL_ALT`. Пример записывает значение в
теневой HL и восстанавливает активный набор.

```text
set_alt_pointer(pointer → HL) clobbers(HL_ALT) {
    push(pointer)
    exx()
    pop(HL)
    exx()
}
```

```asm
set_alt_pointer:
    push hl
    exx
    pop hl
    exx
    ret
```

## Порты и блочные операции

### Чтение порта

Для `in(BC)` вся пара BC задаёт адрес порта. Чтение обновляет флаги и сохраняет CF. В форме
`A = in(0xFE)` старший байт адреса берётся из A до чтения, F сохраняется.

```text
D = in(BC)
```

```asm
    in d, (c)
```

### Запись в порт

`out(BC, E)` записывает E по полному адресу BC. В примере с непосредственным портом A
задаёт и старший байт адреса, и записываемое значение. Обе формы сохраняют F.

```text
out(0xFE, A)
```

```asm
    out (254), a
```

### Блочное копирование

`ldir()` копирует из HL в DE со счётчиком BC. При начальном нуле копируются 65 536 байт.
Направление и повторение задаются выбором `ldi`, `ldir`, `ldd` или `lddr`.
Любая блочная операция принимает либо пустые скобки, либо полный список регистров.
Обе формы читают и меняют одни и те же регистры и флаги. В полной форме EXX проверяет
порядок алиасов. При привязках ниже запись `ldir(src, dst, count)` даст ошибку компиляции.

```text
(dst, src, count) → (DE, HL, BC)
ldir(dst, src, count)
```

```asm
    ldir
```

### Блочный поиск

`cpir()` сравнивает A с байтами начиная с адреса HL до совпадения или исчерпания BC.
Семейство поиска включает `cpi`, `cpir`, `cpd` и `cpdr`.

```text
cpir(HL, A, BC)
```

```asm
    cpir
```

### Блочный ввод

`inir()` заполняет память начиная с адреса HL. C задаёт младший байт адреса порта,
а B задаёт старший байт и служит счётчиком. Семейство ввода включает `ini`, `inir`, `ind` и `indr`.
После блочного ввода или вывода анализатор
разрешает читать Z и считает остальные флаги перезаписанными.

```text
inir(HL, C, B)
```

```asm
    inir
```

### Блочный вывод

`otir()` передаёт в порт байты начиная с HL. При каждой передаче HL увеличивается,
а B уменьшается. Семейство вывода включает `outi`, `otir`, `outd` и `otdr`.

```text
otir(C, HL, B)
```

```asm
    otir
```

## Разработка транслятора

### Регистрация платформы процессора

Токенизатор и парсер в `exxlang/tokenizer.py` и `exxlang/parser.py` строят узлы из
`exxlang/syntax.py`. Зарегистрированная платформа описывает перекрытие регистров, выбирает
инструкции и указывает их эффекты. Для переходов она задаёт цель и возможность продолжения со
следующей команды. Эти данные использует общий анализатор. Так начинается объявление платформы
Z80. [Платформа Z80](exxlang/platforms/z80.py)

```python
@platforms.register
class Z80:
    name = "z80"
    ...
```

### Регистрация таргета ассемблера

Таргет перечисляет поддерживаемые платформы и при необходимости переопределяет заголовок модуля
и запись операндов. Реестры находят модули в `exxlang/platforms/` и `exxlang/targets/`. CLI по
зарегистрированным именам проверяет выбранную комбинацию. [Таргет ASM](exxlang/targets/asm.py)

```python
@targets.register
class PlainAsm(Assembler):
    name = "asm"
    platforms = ("z80",)
```

### Сравнение текста ASM с эталоном

Модульные тесты запускают CLI для каждого `examples/*.exx` и сверяют полный вывод с
`tests/golden/asm/` и `tests/golden/z80asm/`. При расхождении тест показывает изменённые строки.
При намеренном изменении вывода проверьте соответствующие эталоны. Для токенизатора, парсера и
контрактов есть отдельные тесты. Проверки конкретного процессора находятся в `tests/platforms/`.

```sh
python3 -m unittest discover -s tests
```

### Сравнение машинного кода

Скрипт собирает каждый пример обоими ассемблерами и сравнивает байты. Для примера DuoConf он
задаёт одинаковую раскладку и размещает четыре заглушки внешних процедур по одинаковым адресам.
Ассемблеры sjasmplus и z88dk-z80asm берутся из PATH, пути можно указать через `--sjasmplus PATH`
и `--z80asm PATH`.

```sh
python3 tests/assemble_examples.py
```

| Язык | Плюсы и типичные задачи | Ограничения |
| --- | --- | --- |
| **EXX** | Регистры и флаги входят в интерфейс процедуры. Драйвер может вернуть статус в CF вместе с байтом в A, а `keep(BC)` — сохранить счётчик вызывающей стороны при нескольких выходах. EXX проверяет эти условия на ветвлениях и вызовах. | Рабочие регистры выбирает программист, пересылки тоже нужно записывать явно. Даже для сравнения байтов в C и D один из них придётся загрузить в A. Чем больше промежуточных значений, тем больше такой работы. |
| **Wiz** | Структуры, массивы, указатели и доступ к отдельным битам удобны для описания аппаратных данных. Например, `monster.flags$0` прямо обозначает бит поля. Банки и выражения времени компиляции помогают описывать игровые данные и карту памяти. | Допустимые выражения зависят от регистров и способов адресации процессора. Если для выражения нет подходящей инструкции, его приходится разбивать на шаги. При переносе на другую платформу Wiz аппаратно-зависимые участки могут потребовать переработки. [Руководство Wiz](https://github.com/wiz-lang/wiz) · [Примеры битовых полей на Z80](https://github.com/wiz-lang/wiz/blob/5a8ea1ce15953d6ed9d222a54a31cb6447c79121/tests/block/z80_bitindex_i8.wiz) |
| **Z80HLA** | Структурные циклы и ветвления удобны для последовательностей, в которых важна каждая инструкция. Например, `while(nz)` в конце цикла может сразу проверить флаг от `dec a`. Структуры и объединения позволяют дать имена полям данных. | Загрузки, временные регистры и арифметические инструкции выбирает программист. У объявления `function` пустой список параметров, поэтому входные регистры и возвращаемые флаги остаются соглашением между автором и вызывающим кодом. | **C с SDCC** | Локальные переменные, указатели, массивы и составные выражения удобны для парсеров, автоматов состояний и обработки буферов. Регистры распределяет оптимизатор, поэтому ради ещё одного промежуточного значения редко приходится переписывать всю процедуру. | Последовательность инструкций зависит от оптимизации. Для цикла с заданным числом тактов приходится изучать сгенерированный ASM. Если процедура возвращает аппаратный флаг как дополнительный результат, может понадобиться обёртка на ассемблере. [Руководство SDCC](https://sdcc.sourceforge.net/doc/sdccman.pdf) |
