# EXX

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.md) [![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

EXX переводит процедуры с высокоуровневого ассемблера в исходный код на ассемблере Z80.
Каждая процедура объявляет свой регистровый интерфейс (ABI). Это позволяет
заменить процедуру в банке ПЗУ или собрать объектный модуль для библиотеки
z88dk, сохранив существующий порядок вызова. Транслятору нужен Python 3.10
или новее. Все зависимости входят в стандартную библиотеку.

```text
extern video_stack_safe(window → B, session: VID_SESSION → IX)
    → (CF, A) clobbers(C, HL, F)

check_window(window → B, session: VID_SESSION → IX)
    → (CF, A) clobbers(C, HL, F) {
    (CF, A) = video_stack_safe(window, session)
    if (CF) return (CF, A)
    return (0, 1)
}
```

Аргументы уже находятся в B и IX. Вызов и проверка ошибки превращаются
в `call video_stack_safe` и `ret c`. При успехе выполняются `xor a`,
`inc a` и `ret`. Вызывающая процедура получает A = 1 и сброшенный флаг переноса.

## Сборка модуля

```sh
./exx --target asm examples/sdk_console_cursor.exx -o cursor.asm
./exx --target z80asm --section code_clib examples/sdk_console_cursor.exx -o cursor_z80asm.asm
z88dk-z80asm cursor_z80asm.asm
```

Таргет `asm` выдаёт фрагмент с метками, инструкциями и запрошенными директивами
включения файлов. Исходник, в который включают этот фрагмент, задаёт размещение
кода и определения символов, в том числе смещений полей вида `VID_CTX.config`.
В sjasmplus добавьте `INCLUDE "cursor.asm"` в нужный банк.

Таргет `z80asm` выдаёт модуль для `z88dk-z80asm`. Директива `PUBLIC`
открывает имена процедур для других модулей, а `EXTERN` объявляет процедуры,
которые модуль вызывает извне. Полученный объектный файл можно слинковать
с объектными файлами, собранными из обычного ASM. Для вызова из C потребуется
совместимое регистровое соглашение или адаптер на ассемблере.

Без `-o` EXX выводит ассемблерный текст в стандартный поток вывода.
Оба таргета используют одну и ту же последовательность инструкций Z80.
Процессор можно выбрать явно с помощью `--platform z80`. Если указать только
`--target`, EXX выберет первую платформу из списка поддерживаемых таргетом.

При раздельной компиляции поместите общие объявления `extern` в файл
и передайте его при сборке каждого модуля. EXX сверяет определение процедуры
с объявлением по регистрам и типам входных параметров, порядку результатов
и списку `clobbers`. Вызывающий модуль берёт объявление из того же файла.

```sh
./exx --target z80asm --abi video.abi video.exx -o video.asm
./exx --target z80asm --abi video.abi caller.exx -o caller.asm
```

Опцию `--abi` можно повторить для нескольких файлов. Процедура, написанная
на ассемблере, должна соблюдать объявленный для неё контракт.

Чтобы Make заново генерировал ассемблерный файл при изменении исходника
или транслятора, подключите `exx.mk` и добавьте правило сборки.

```make
include path/to/exx/exx.mk
EXX_TARGET := asm
# Для модулей с общими объявлениями процедур:
# EXX_ABI := video.abi

build/%.asm: src/%.exx $(EXX_TOOL_DEPS)
	$(exx_compile)
```

## Регистровые контракты

- Привязка `window → B` даёт параметру имя. Так же можно объявить локальные имена
  `(window, page) → (B, E)`. Каждое имя обозначает текущее содержимое
  физического регистра. Для пересылки значения используется присваивание.
- При вызове EXX проверяет число аргументов и их расположение. Если процедура
  принимает аргумент в E, а значение находится в D, перед вызовом запишите `E = D`.
- Процедура может вернуть несколько значений, например `→ (A, HL, DE)`.
  Чтобы получить их в месте вызова, перечислите регистры или их имена в порядке
  объявления. Если результаты не нужны, запишите вызов отдельным оператором.
  В самой процедуре `return (status, cursor, remaining)` помещает значения
  в объявленные регистры. Если для перестановки нужен временный регистр,
  пересылки нужно записать явно. При совпадении регистровых контрактов результата
  `return helper(args)` превращается в хвостовой переход. Внешняя процедура
  должна быть доступна при текущем отображении памяти.
- `clobbers(C, HL, F)` разрешает вызываемой процедуре изменять эти регистры.
  Если регистр или флаг также объявлен результатом, после вызова он содержит
  доступное для чтения значение. Для чтения значение должно быть определено
  на каждом пути к данной точке, в том числе при переходе на следующую итерацию
  цикла. Анализ учитывает перекрытие пар BC, DE, HL и AF с их составными
  регистрами. F охватывает шесть документированных флагов состояния.
  SP зарезервирован для стека вызовов.
- `if (CF)` и `if (Z)` читают текущие флаги. Для `if (A)` и `if (!A)`
  транслятор проверяет аккумулятор командой `or a`, которая изменяет F.
  Укажите изменяемые регистры и флаги среди результатов или в `clobbers`.
  Сравнения беззнаковые. При сравнении двух байтов одним из операндов должен
  быть A. Операторы `&&` и `||` вычисляют правую часть только тогда, когда
  левая ещё не определила результат.
- Присваивание в скобках можно использовать как операнд условия в `if` и
  `while`. В выражении `if ((A = session->action) == RST8_VID_PREP_DRAW)`
  поле загружается в A один раз, затем следует сравнение. В условии
  `if (Z && (A = session->action) == 1)` загрузка выполняется только при
  установленном Z. На этом пути в A остаётся прочитанный байт, а на другом
  пути сохраняется прежнее значение A. Вместо A можно использовать его алиас.

## Выражения и раскладка структур

EXX поддерживает `if`/`else`, `while`, вызовы, возвраты, загрузку байтов
и непосредственных значений в регистровые пары, арифметику и XOR с аккумулятором,
а также отдельные операции с парами. Регистр назначения указывается явно.
Чтобы получить сумму B и C в A, запишите `A = B`, затем `A += C`.
При неподдерживаемой форме инструкции EXX указывает строку исходника.
Операторы можно разделять переводами строк или точками с запятой.

В объявлении `context: VID_CTX → IY` имя типа задаёт префикс для смещений
байтовых полей. Для sjasmplus присваивание `A = context->config` превращается
в `ld a,(iy + VID_CTX.config)`. Таргет `z80asm` использует имя
`VID_CTX_config`. Определите раскладку и константы в основном ассемблерном
файле или подключите их через `--include layout.inc`. Имена констант
в верхнем регистре и имена вида `VID_CTX.slot0` передаются ассемблеру как
символы. Числовые смещения полей и адреса банков определяются при ассемблировании.
При передаче IY напрямую или через локальный алиас EXX сверяет имя типа,
объявленного для IY в вызывающей процедуре, с типом параметра. За адрес
в регистре отвечает вызывающая сторона.

Транслятор проверяет, какие регистры и флаги доступны на каждом пути выполнения.
Если смысл результата зависит от условия, укажите это в описании ABI процедуры.
Например, «при установленном CF регистр A содержит код ошибки». Для внешних
ASM-процедур EXX опирается на объявленный контракт. Выбор регистров, работа
с кадрами стека и сохранение регистров остаются за программистом.

## Примеры и проверка

Токенизатор находится в `exxlang/tokenizer.py`, парсер — в `exxlang/parser.py`.
Парсер строит синтаксическое дерево из узлов, описанных в `exxlang/syntax.py`.
За выбор инструкций Z80 отвечает `exxlang/platforms/z80.py`. Каждая платформа
регистрирует свой класс через `@platforms.register`, описывает регистры,
выбирает инструкции и указывает, что они читают и изменяют. Для условного
перехода платформа явно задаёт целевую метку и возможность продолжить выполнение
со следующей инструкции. Этими данными пользуется общий анализатор потока управления.

Каждый таргет в `exxlang/targets/` регистрирует свой класс через
`@targets.register` и перечисляет имена поддерживаемых платформ. Таргет
может унаследовать общий код вывода ассемблера и переопределить заголовок
модуля и запись операндов. Реестры находят модули в соответствующих пакетах.
Интерфейс командной строки получает допустимые имена из реестров и проверяет
совместимость выбранных платформы и таргета. Для токенизатора, парсера
и регистровых контрактов есть отдельные модульные тесты. Тесты конкретных
процессоров находятся в `tests/platforms/`.

- [video_plan_plane.exx](examples/video_plan_plane.exx) реализует выбор
  видеоплоскости в DuoConf. Процедура обращается к полям через индексные
  регистры, вызывает внешние процедуры и возвращает результат во флагах.
- [sdk_console_cursor.exx](examples/sdk_console_cursor.exx) реализует две
  процедуры работы с курсором из zxevo-sdk с исходным ABI в регистрах BC и DE.
- [advance_block.exx](examples/advance_block.exx) показывает цикл и возврат
  трёх значений в A, HL и DE.

```sh
python3 -m unittest discover -s tests
python3 tests/assemble_examples.py
```

В составе модульных тестов EXX компилирует каждый `examples/*.exx` через CLI.
Тест сравнивает полный вывод с эталонами `tests/golden/asm/<имя>.asm` и
`tests/golden/z80asm/<имя>.asm` и при расхождении показывает изменившиеся строки.
При намеренном изменении генерации проверьте и обновите соответствующие эталоны.

Для проверки сборки нужны `sjasmplus` и `z88dk-z80asm` в `PATH`. Скрипт
собирает каждый пример обоими ассемблерами и сравнивает полученные байты.
Для примера DuoConf он задаёт константы раскладки и размещает четыре заглушки
внешних процедур по одинаковым адресам в обеих сборках. Пути к другим
установкам можно указать через `--sjasmplus PATH` и `--z80asm PATH`.

## Арифметика и биты

### Числовые литералы

Доступны десятичная, шестнадцатеричная и двоичная записи. Оба присваивания загружают 128.

```text
A = 0x80
B = 0b10000000
```

```asm
    ld a, 128
    ld b, 128
```

### Арифметика с аккумулятором

Укажите регистр назначения явно. Чтобы сложить B и C, перенесите B в A и прибавьте C. Операторы
разделяются переводом строки или точкой с запятой. Для неподдерживаемой формы EXX указывает
строку исходника.

```text
A = B
A += C
```

```asm
    ld a, b
    add a, c
```

### Арифметика регистровых пар

Указатель можно увеличить или уменьшить непосредственно в регистровой паре. Сложение `HL += DE`
даёт `add hl,de`.

```text
HL += DE
HL -= 1
```

```asm
    add hl, de
    dec hl
```

### Проверка бита

`$` выбирает бит с постоянным номером от 0 до 7. Проверка регистра или индексного поля
использует `bit` и сохраняет CF.

```text
if (packet->status$3) return 1
return 0
```

```asm
    bit 3, (iy + PACKET.status)
    jp z, exx__example_1
    ld a, 1
    ret
exx__example_1:
    ld a, 0
    ret
```

### Запись бита

Присваивание `true` даёт `set`, а `false` — `res`. Обе команды сохраняют F.

```text
packet->status$3 = false
```

```asm
    res 3, (iy + PACKET.status)
```

### Маска AND

`&=` оставляет в A биты, заданные маской. Этот пример даёт `and 127` и обновляет F.

```text
A &= ~(1 << 7)
```

```asm
    and 127
```

### Маска OR

`|=` устанавливает в A указанные маской биты. Здесь получится `or 128` с обновлением F.

```text
A |= 0x80
```

```asm
    or 128
```

### Исключающее ИЛИ

`^=` инвертирует биты по маске. Для операнда в E получится `xor e` с обновлением F.

```text
A ^= E
```

```asm
    xor e
```

### Инверсия байта

`~A` инвертирует все восемь битов командой `cpl`. CF, S, Z и PV сохраняются.

```text
A = ~A
```

```asm
    cpl
```

### Логические сдвиги байта

`<<=` сдвигает влево, а `>>=` — вправо с заполнением нулями. Байтовые сдвиги и вращения
принимают регистр или индексное поле и число шагов от 0 до 255, известное EXX. Каждый шаг
обновляет F. При нуле шагов значение и флаги сохраняются.

```text
B >>= 2
```

```asm
    srl b
    srl b
```

### Арифметический сдвиг вправо

`sra` на каждом шаге заполняет старший бит знаковым. Именованные операции сдвига
и вращения по умолчанию выполняют один шаг.

```text
sra(D, 2)
```

```asm
    sra d
    sra d
```

### Сдвиг слова влево

Сдвиг HL влево на один разряд даёт `add hl,hl`. Команда обновляет CF, HF и N и сохраняет
остальные документированные флаги.

```text
HL <<= 1
```

```asm
    add hl, hl
```

### Циклические вращения

`rlc` вращает байт влево, а `rrc` — вправо. Вытесненный бит попадает на другой конец
байта и одновременно копируется в CF.

```text
rlc(B)
```

```asm
    rlc b
```

### Вращения через перенос

`rl` и `rr` используют CF как дополнительный бит. В этом примере
`sra d` помещает младший бит D в CF, затем `rr e` переносит его в старший бит E.

```text
sra(D)
rr(E)
```

```asm
    sra d
    rr e
```

### Сложение с переносом

`adc` прибавляет к первому операнду второй и входной CF, затем обновляет F. На Z80
доступны формы с A и HL.

```text
adc(HL, DE)
```

```asm
    adc hl, de
```

### Вычитание с заёмом

`sbc` вычитает из первого операнда второй и входной CF, затем обновляет F. Здесь
получится `sbc a,e`.

```text
sbc(A, E)
```

```asm
    sbc a, e
```

### Счётный цикл

`repeat` выполняет тело, затем уменьшает B командой `djnz`, которая сохраняет флаги. При
начальном нуле будет 256 итераций, если тело сохраняет B. Если обратный переход может оказаться
слишком дальним, EXX использует ближнюю метку для `djnz` и абсолютные переходы.

```text
count → B
count = 16
repeat (count) {
    *HL = A
    HL += 1
}
```

```asm
    ld b, 16
exx__example_1:
    ld (hl), a
    inc hl
    djnz exx__example_1
```

### Досрочный выход из цикла

`break` выходит из ближайшего `while` или `repeat`. Здесь при нулевом байте выход происходит до
изменения HL и B.

```text
repeat (B) {
    if (!(A = *HL)) break
    HL += 1
}
```

```asm
exx__example_1:
    ld a, (hl)
    or a
    jp z, exx__example_2
    inc hl
    djnz exx__example_1
exx__example_2:
```

## Память и символы

### Байтовые указатели

`*ptr` обращается к байту по адресу в BC, DE, HL, IX или IY. При адресации через BC или DE байт
передаётся через A. Здесь получаются `ld a,(de)` и `ld (hl),a`.

```text
(src, dst) → (DE, HL)
A = *src
*dst = A
```

```asm
    ld a, (de)
    ld (hl), a
```

### Индексная адресация

Для указателя в IX или IY допустимо постоянное смещение от −128 до 127. Символьное смещение
вычисляет основной ассемблер.

```text
previous(cursor → IX) → A { return cursor[-1] }
```

```asm
previous:
    ld a, (ix - 1)
    ret
```

### Типизированные поля структур

Имя раскладки задаёт префикс смещений и проверяется при передаче указателя по имени, через алиас
или физический регистр. Для загрузки байта ниже таргет `asm` использует `VID_CTX.config`, а
`z80asm` — `VID_CTX_config`. За адрес отвечает вызывающая сторона.

```text
config(ctx: VID_CTX → IY) → A { return ctx->config }
```

```asm
config:
    ld a, (iy + VID_CTX.config)
    ret
```

### 16-битные поля

По умолчанию поле имеет ширину `u8`. При ширине `u16` EXX читает или пишет два байта, начиная с
младшего. Оба смещения должны попадать в диапазон индекса. Слово может находиться в BC, DE или
HL. Можно также записать константу.

```text
field DRV_HEADER.ops: u16
install(h: DRV_HEADER → IY, table → HL) { h->ops = table }
```

```asm
install:
    ld (iy + DRV_HEADER.ops), l
    ld (iy + DRV_HEADER.ops + 1), h
    ret
```

### Адреса внешних данных

Объявите символ данных через `extern data` и возьмите его адрес оператором `&`. Таргет `z80asm`
добавит `EXTERN` для используемых данных.

```text
extern data bs_storage_ops
table_address() → HL { return &bs_storage_ops }
```

```asm
table_address:
    ld hl, bs_storage_ops
    ret
```

### Константы ассемблера

Имена в верхнем регистре и квалифицированные имена смещений передаются в ASM как символы. Их
значения и адреса банков задаёт основной проект.

```text
A = VID_CTX.slot0 ^ VID_CTX.slot1
```

```asm
    ld a, 0 + (VID_CTX.slot0 ^ VID_CTX.slot1)
```

## Стек и наборы регистров

### Сохранение в стеке

`push` сохраняет слово, а `pop` загружает его в выбранную пару. EXX отслеживает
инициализированные части слова и после вызова. Здесь процедура сохраняет BC по своему ABI. На
слиянии веток глубина стека должна совпадать, при любом выходе, включая хвостовой переход, —
равняться входной. SP зарезервирован для стека вызовов. При записи через указатели следите за
сохранностью слов на стеке.

```text
extern work() clobbers(BC)
run_preserving_bc() {
    push(BC)
    work()
    pop(BC)
}
```

```asm
run_preserving_bc:
    push bc
    call work
    pop bc
    ret
```

### Обмен регистровых пар

Обмен DE и HL выполняется одной командой. Записи `ex(DE, HL)` и `ex(HL, DE)` дают одинаковый код.

```text
ex(DE, HL)
```

```asm
    ex de, hl
```

### Обмен с вершиной стека

`ex_sp` обменивает HL, IX или IY со словом на вершине стека. Здесь IX получает прежнее
значение BC, затем DE получает прежнее значение IX.

```text
push(BC)
ex_sp(IX)
pop(DE)
```

```asm
    push bc
    ex (sp), ix
    pop de
```

### Теневые регистры

`ex(AF)` даёт `ex af,af'`. Вызов `exx()` обменивает BC, DE и HL с их теневыми парами. В сигнатуре
теневые пары обозначаются `AF_ALT`, `BC_ALT`, `DE_ALT` и `HL_ALT`. Пример записывает значение в
теневой HL и восстанавливает активный набор.

```text
set_alt_pointer(pointer → HL) clobbers(HL_ALT) {
    push(pointer)
    exx()
    pop(HL)
    exx()
}
```

```asm
set_alt_pointer:
    push hl
    exx
    pop hl
    exx
    ret
```

## Порты и блочные операции

### Чтение порта

Для `in(BC)` вся пара BC задаёт адрес порта. Чтение обновляет флаги и сохраняет CF. В форме
`A = in(0xFE)` старший байт адреса берётся из A до чтения, F сохраняется.

```text
D = in(BC)
```

```asm
    in d, (c)
```

### Запись в порт

`out(BC, E)` записывает E по полному адресу BC. В примере с непосредственным портом A
задаёт и старший байт адреса, и записываемое значение. Обе формы сохраняют F.

```text
out(0xFE, A)
```

```asm
    out (254), a
```

### Блочное копирование

`ldir()` копирует из HL в DE со счётчиком BC. При начальном нуле копируются 65 536 байт.
Направление и повторение задаются выбором `ldi`, `ldir`, `ldd` или `lddr`.
Любая блочная операция принимает либо пустые скобки, либо полный список регистров.
Обе формы читают и меняют одни и те же регистры и флаги. В полной форме EXX проверяет
порядок алиасов. При привязках ниже запись `ldir(src, dst, count)` даст ошибку компиляции.

```text
(dst, src, count) → (DE, HL, BC)
ldir(dst, src, count)
```

```asm
    ldir
```

### Блочный поиск

`cpir()` сравнивает A с байтами начиная с адреса HL до совпадения или исчерпания BC.
Семейство поиска включает `cpi`, `cpir`, `cpd` и `cpdr`.

```text
cpir(HL, A, BC)
```

```asm
    cpir
```

### Блочный ввод

`inir()` заполняет память начиная с адреса HL. C задаёт младший байт адреса порта,
а B задаёт старший байт и служит счётчиком. Семейство ввода включает `ini`, `inir`, `ind` и `indr`.
После блочного ввода или вывода анализатор
разрешает читать Z и считает остальные флаги перезаписанными.

```text
inir(HL, C, B)
```

```asm
    inir
```

### Блочный вывод

`otir()` передаёт в порт байты начиная с HL. При каждой передаче HL увеличивается,
а B уменьшается. Семейство вывода включает `outi`, `otir`, `outd` и `otdr`.

```text
otir(C, HL, B)
```

```asm
    otir
```
