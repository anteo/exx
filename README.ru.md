# EXX

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.md) [![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

EXX переводит высокоуровневый ассемблер в символический Z80 ASM.
Процедуры объявляют входные регистры, результаты и регистры,
которые могут изменить.
EXX требует Python 3.10 или новее и использует только стандартную библиотеку.

[Руководство по синтаксису](MANUAL.ru.md)

## Пример

Процедура возвращает меньший из двух беззнаковых байтов. Аргументы
передаются в A и B, результат возвращается в A, а сравнение меняет флаги в F.

```text
minimum(value → A, limit → B) → A clobbers(F) {
    if (value < limit) return value
    return limit
}
```

```asm
minimum:
    cp b
    ret c
    ld a, b
    ret
```

## Сборка модуля

### Фрагмент для включения в ASM

Таргет `asm` выдаёт фрагмент Z80 ASM для включения в ассемблерный проект.
Адрес размещения задаёт основной ассемблерный файл. Примеры проверены
со sjasmplus, где фрагмент подключается через `INCLUDE "cursor.asm"`.

```sh
./exx --target asm examples/sdk_console_cursor.exx -o cursor.asm
```

Обе процедуры курсора теперь можно подключить одним файлом. [Полученный cursor.asm](tests/golden/asm/sdk_console_cursor.asm)

### Модуль для линковки

Таргет `z80asm` оформляет те же инструкции директивами `SECTION`, `PUBLIC` и `EXTERN` для
`z88dk-z80asm`. Объектный файл можно слинковать с другими ASM-модулями. Для вызова из C
потребуется совместимое соглашение о вызовах или адаптер на ASM.

```sh
./exx --target z80asm --section code_clib examples/sdk_console_cursor.exx -o cursor.asm
z88dk-z80asm cursor.asm
```

Полученный модуль начинается с этих директив.

```asm
    SECTION code_clib
    PUBLIC zx__console_newline
    PUBLIC zx__console_advance
```

### Выбор процессора

Процессор задаётся через `--platform`. По умолчанию EXX выбирает первую платформу таргета. Без
`-o` ассемблерный текст выводится в stdout.

```sh
./exx --platform z80 --target asm examples/advance_block.exx
```

В выводе видны процедура и вызывающий её код. [Полученный advance_block.asm](tests/golden/asm/advance_block.asm)

### Подключение файлов ассемблера

Опция `--include` подключает определения раскладок и констант перед сгенерированными процедурами.

```sh
./exx --target asm --include layout.inc examples/buffer.exx -o buffer.asm
```

```asm
    INCLUDE "layout.inc"
```

### Общие объявления ABI

Передайте один файл объявлений вызывающему и вызываемому модулям. EXX сверит входные регистры и
типы, порядок результатов и `clobbers`. Для нескольких файлов повторите `--abi`. Реализация на
ASM должна соблюдать объявленный контракт.

```sh
./exx --target z80asm --abi video.abi video.exx -o video.asm
./exx --target z80asm --abi video.abi caller.exx -o caller.asm
```

Например, в `video.abi` объявлена процедура `extern read_page(page → E) → A`.
Если в `video.exx` записать `read_page(page → E) → A { return page }`, а в `caller.exx` —
`fetch_page(page → E) → A { return read_page(page) }`, оба модуля будут ссылаться на одно имя.

```asm
; video.asm
    SECTION code_user
    PUBLIC read_page

read_page:
    ld a, e
    ret
```

```asm
; caller.asm
    SECTION code_user
    PUBLIC fetch_page
    EXTERN read_page

fetch_page:
    jp read_page
```

### Интеграция с Make

Подключите `exx.mk`, чтобы Make пересобирал ASM при изменении исходника, транслятора или общего
файла из `EXX_ABI`.

```make
include path/to/exx/exx.mk
EXX_TARGET := asm
EXX_ABI := video.abi

build/%.asm: src/%.exx $(EXX_TOOL_DEPS)
	$(exx_compile)
```

## Подсветка в редакторах

Zed и VS Code распознают файлы `.exx` и подсвечивают синтаксис EXX и вставки
Z80 ASM цветами текущей темы. `make install` из корня репозитория собирает и
устанавливает расширения для найденных редакторов. Если редактор отсутствует,
команда сообщает об этом и пропускает его. Ошибка сборки или установки даёт
ненулевой код завершения. Поиск идёт по командам `zed`, `zeditor` и `code` в
`PATH`, а на macOS ещё и по системной и пользовательской папкам Applications.

- **Zed.** `make zed-install` регистрирует `build/zed/exx` как локальное расширение.
  Этот каталог нужен и после установки. Если Zed открыт, перезапустите его.
  Для установки через редактор выполните
  `make zed` и укажите `build/zed/exx` через **Install Dev Extension**. Для сборки
  нужны Node.js и [Tree-sitter CLI](https://tree-sitter.github.io/tree-sitter/cli/).
  При первой сборке Tree-sitter может скачать WASI SDK.
- **VS Code.** `make vscode-install` использует CLI редактора. Переменная `CODE`
  задаёт путь к нужной команде. Для сборки нужны Node.js 20 или новее и npm.
  Для установки через редактор выполните `make vscode` и укажите
  `build/exx.vsix` через **Extensions: Install from VSIX**.

`make editors` собирает оба расширения, а на macOS ещё и Quick Look.

## Quick Look в macOS

Расширение Quick Look показывает `.exx` в Finder с подсветкой ключевых слов,
регистров и флагов Z80, чисел, строк и комментариев. Для сборки нужны
инструменты разработки macOS. Запустите из корня репозитория.

```sh
make quicklook-install
```

Скрипт регистрирует расширение в `~/Applications/EXX File Type.app`.
Выберите файл EXX в Finder и нажмите пробел.
Для отдельной сборки выполните `make quicklook`. Подписанное приложение
появится в `build/quicklook/`.

## Автоматический выбор длины перехода

Для таргетов `asm` и `z80asm` EXX генерирует `jr` для безусловного перехода
и условий `Z`, `NZ`, `C`, `NC`, если от конца инструкции до цели от −128 до +127 байт.
Это правило действует и для хвостового перехода к другой процедуре в том же модуле.
Для остальных условий, внешних символов и переходов через вставку ASM
используется `jp`. Инструкции внутри `asm` передаются ассемблеру как написаны.

[Пример условного ветвления](MANUAL.ru.md#условное-ветвление)

## Сравнение языков

| Язык | Плюсы и типичные задачи | Ограничения |
| --- | --- | --- |
| **EXX** | Регистры и флаги входят в интерфейс процедуры. Драйвер может вернуть статус в CF вместе с байтом в A, а `keep(BC)` — сохранить счётчик вызывающей стороны при нескольких выходах. EXX проверяет эти условия на ветвлениях и вызовах. | Рабочие регистры выбирает программист, пересылки тоже нужно записывать явно. Даже для сравнения байтов в C и D один из них придётся загрузить в A. Чем больше промежуточных значений, тем больше такой работы. |
| **Wiz** | Структуры, массивы, указатели и доступ к отдельным битам удобны для описания аппаратных данных. Например, `monster.flags$0` прямо обозначает бит поля. Банки и выражения времени компиляции помогают описывать игровые данные и карту памяти. | Допустимые выражения зависят от регистров и способов адресации процессора. Если для выражения нет подходящей инструкции, его приходится разбивать на шаги. При переносе на другую платформу Wiz аппаратно-зависимые участки могут потребовать переработки. [Руководство Wiz](https://github.com/wiz-lang/wiz) · [Примеры битовых полей на Z80](https://github.com/wiz-lang/wiz/blob/5a8ea1ce15953d6ed9d222a54a31cb6447c79121/tests/block/z80_bitindex_i8.wiz) |
| **Z80HLA** | Структурные циклы и ветвления удобны для последовательностей, в которых важна каждая инструкция. Например, `while(nz)` в конце цикла может сразу проверить флаг от `dec a`. Структуры и объединения позволяют дать имена полям данных. | Загрузки, временные регистры и арифметические инструкции выбирает программист. У объявления `function` пустой список параметров, поэтому входные регистры и возвращаемые флаги остаются соглашением между автором и вызывающим кодом. [Руководство Z80HLA](https://github.com/internalregister/z80hla/blob/master/MANUAL.md) |
| **C с SDCC** | Локальные переменные, указатели, массивы и составные выражения удобны для парсеров, автоматов состояний и обработки буферов. Регистры распределяет оптимизатор, поэтому ради ещё одного промежуточного значения редко приходится переписывать всю процедуру. | Последовательность инструкций зависит от оптимизации. Для цикла с заданным числом тактов приходится изучать сгенерированный ASM. Если процедура возвращает аппаратный флаг как дополнительный результат, может понадобиться обёртка на ассемблере. [Руководство SDCC](https://sdcc.sourceforge.net/doc/sdccman.pdf) |

### Интеграция в сборку

| Инструмент | Что получается и как подключить |
| --- | --- |
| **EXX** | Вывод `asm` подключается в исходник основного ассемблера. Вывод `z80asm` можно собрать через `z88dk-z80asm` и передать объектный файл линкеру. [Сборка модуля](#сборка-модуля) |
| **Wiz** | Wiz размещает банки и формирует бинарник или образ ПЗУ одной из поддерживаемых консолей. При включении отдельно собранного бинарника нужно согласовать его размещение и адреса внешних символов с основным проектом. [Форматы вывода Wiz](https://github.com/wiz-lang/wiz#features) |
| **Z80HLA** | Ассемблер читает один входной файл, обрабатывает его включения и выдаёт бинарник. При необходимости можно получить листинг инструкций. [Параметры Z80HLA](https://github.com/internalregister/z80hla#using-it) |
| **SDCC** | `sdcc -mz80 -c` выдаёт объектный модуль для совместимого линкера, а `sdcc -mz80 -S` позволяет посмотреть ASM. При совместном использовании модулей на C и ASM нужно согласовать соглашение о вызовах. [Руководство SDCC](https://sdcc.sourceforge.net/doc/sdccman.pdf) |

## Разработка транслятора

### Регистрация платформы процессора

Токенизатор и парсер в `exxlang/tokenizer.py` и `exxlang/parser.py` строят узлы из
`exxlang/syntax.py`. Зарегистрированная платформа описывает перекрытие регистров, выбирает
инструкции и указывает их эффекты. Для переходов она задаёт цель и возможность продолжения со
следующей команды. Эти данные использует общий анализатор. Так начинается объявление платформы
Z80. [Платформа Z80](exxlang/platforms/z80.py)

```python
@platforms.register
class Z80:
    name = "z80"
    ...
```

### Регистрация таргета ассемблера

Таргет перечисляет поддерживаемые платформы и при необходимости переопределяет заголовок модуля
и запись операндов. Реестры находят модули в `exxlang/platforms/` и `exxlang/targets/`. CLI по
зарегистрированным именам проверяет выбранную комбинацию. [Таргет ASM](exxlang/targets/asm.py)

```python
@targets.register
class PlainAsm(Assembler):
    name = "asm"
    platforms = ("z80",)
```

### Сравнение текста ASM с эталоном

Модульные тесты запускают CLI для каждого `examples/*.exx` и сверяют полный вывод с
`tests/golden/asm/` и `tests/golden/z80asm/`. При расхождении тест показывает изменённые строки.
При намеренном изменении вывода проверьте соответствующие эталоны. Для токенизатора, парсера и
контрактов есть отдельные тесты. Проверки конкретного процессора находятся в `tests/platforms/`.

```sh
make test
```

### Сравнение машинного кода

Скрипт собирает каждый пример обоими ассемблерами и сравнивает байты. Для примера DuoConf он
задаёт одинаковую раскладку и размещает четыре заглушки внешних процедур по одинаковым адресам.
Ассемблеры sjasmplus и z88dk-z80asm берутся из PATH. Пути можно задать
переменными `SJASMPLUS` и `Z88DK_Z80ASM`.

```sh
make test-asm
```
