## Как читать примеры

Под каждым примером EXX приведён вывод таргета `asm`, если явно не указан другой таргет.
Для фрагментов тела процедуры показаны соответствующие инструкции и метки переходов.
Метка входа в окружающую процедуру и её неявный завершающий `ret` опущены.
В этих фрагментах `session` — указатель на `VID_SESSION` в IX, а `packet` — указатель на `PACKET` в IY.

## Процедуры и регистры

### Регистровый ABI

Результат указывается перед именем процедуры как в определении, так и в
объявлении `extern`. Для одного результата пишите имя регистра или флага,
например `A read_byte()`. Для нескольких используйте список в скобках,
например `(CF, A) probe()`. Заголовок процедуры без результата начинается
с имени, как в `reset()`. Стрелки привязывают параметры к регистрам, а
`clobbers(...)` после списка параметров описывает изменения регистров и флагов.

```text
extern (CF, A) video_stack_safe(window → B, session: VID_SESSION → IX) clobbers(C, HL, F)

(CF, A) check_window(window → B, session: VID_SESSION → IX) clobbers(C, HL, F) {
    (CF, A) = video_stack_safe(window, session)
    if (CF) return (CF, A)
    return (0, 1)
}
```

```asm
check_window:
    call video_stack_safe
    ret c
    xor a
    inc a
    ret
```

Аргументы уже находятся в B и IX. Вызов и проверка ошибки превращаются
в `call video_stack_safe` и `ret c`. При успехе выполняются `xor a`,
`inc a` и `ret`. Вызывающая процедура получает A = 1 и сброшенный флаг переноса.

### Комментарии исходника

Все таргеты переносят комментарии `//` и `/* … */` в ASM отдельными строками с `;`.
Описание процедуры появляется перед её меткой. Если оператор не даёт инструкций,
комментарий остаётся в исходном порядке рядом с остальным кодом.

```text
// Вернуть номер страницы, переданный вызывающей стороной.
A read_page(page → E) {
    /* Вызывающая сторона ждёт результат в A. */
    return page
}
```

```asm
; Вернуть номер страницы, переданный вызывающей стороной.
read_page:
    ; Вызывающая сторона ждёт результат в A.
    ld a, e
    ret
```

### Параметры в регистрах

Стрелка связывает имя параметра с физическим регистром. Здесь при входе `page` уже находится в E.

```text
A read_page(page → E) { return page }
```

```asm
read_page:
    ld a, e
    ret
```

### Плотная раскладка параметров на стеке

Типизированный параметр без привязки к регистру лежит на стеке. EXX начинает
со смещения 2 от входного SP, сразу после адреса возврата, и размещает стековые
параметры по порядку объявления без выравнивания. `u8` занимает один байт,
`u16` два байта с младшим первым. Параметры в регистрах места на стеке не
занимают. Для чтения параметров укажите `frame(IX)` или `frame(IY)`.

```text
A read_character(mode: u8, pointer: u16, character: u8)
    frame(IX) clobbers(CF, HF, N) {
    return character
}
```

```asm
read_character:
    push ix
    ld ix, 0
    add ix, sp
    ld a, (ix + 7)
    pop ix
    ret
```

### Явные смещения на стеке

`имя: тип → stack[n]` задаёт смещение в байтах от входного SP. По смещениям
0 и 1 лежит адрес возврата. Параметры не должны перекрываться. Параметр без
явного смещения начинается после всех ранее объявленных стековых параметров,
включая параметры с явным смещением. В `extern` можно записать ту же
раскладку любой из двух форм.

```text
HL read_length(length: u16 → stack[6]) frame(IY) {
    return length
}
```

```asm
read_length:
    push iy
    push af
    ld iy, 2
    add iy, sp
    pop af
    ld l, (iy + 8)
    ld h, (iy + 8 + 1)
    pop iy
    ret
```

### Стековый кадр

`frame(IX)` или `frame(IY)` пишется после списка параметров перед
`clobbers(...)`. Выбранный регистр указывает на своё сохранённое значение.
Смещения аргументов от регистра кадра поэтому на два байта больше смещений
от входного SP. Все байты каждого аргумента должны укладываться в диапазон
индексной адресации Z80. Регистр кадра доступен в теле и в вызовах вспомогательных
процедур с регистровым ABI, которые его сохраняют. EXX восстанавливает регистр
при раннем возврате, в конце процедуры и при хвостовом переходе.

```text
extern inspect(frame_pointer → IY)
A read_byte(value: u8) frame(IY) clobbers(CF, HF, N) {
    inspect(IY)
    A = value
}
```

```asm
read_byte:
    push iy
    ld iy, 0
    add iy, sp
    call inspect
    ld a, (iy + 4)
    pop iy
    ret
```

Если любой из флагов CF, HF и N передаётся на вход или должен сохраниться,
пролог сохраняет AF на время вычисления адреса, как в `read_length`.
ABI процедуры должен сохранять регистр кадра. При неиспользуемых стековых
параметрах кадр можно опустить. Стековые параметры доступны только для чтения.
Байты аргументов после возврата снимает вызывающий код. Для подготовки
исходящего вызова со стековыми аргументами используйте блок `asm`.

### Размер структуры на стеке

`layout NAME: размер` сообщает EXX, сколько байт занимает аргумент, переданный
по значению. `field` задаёт тип поля, доступного через точку, например
`surface.page0`. Если объявления `field` нет, EXX считает поле байтом (`u8`).
Объявления `layout` и `field` можно вынести в общий ABI-файл EXX.

```text
layout DRAW_SURFACE: 3
field DRAW_SURFACE.page0: u8

A read_page(mode: u8, surface: DRAW_SURFACE) frame(IX) clobbers(CF, HF, N) {
    return surface.page0
}
```

Ассемблеру также нужно смещение поля в байтах. В этом примере исходный ASM
или подключаемый файл содержит определение

```asm
DRAW_SURFACE.page0 equ 1
```

Для z88dk-z80asm используется запись `DEFC DRAW_SURFACE_page0 = 1`.

```asm
read_page:
    push ix
    ld ix, 0
    add ix, sp
    ld a, (ix + 5 + DRAW_SURFACE.page0)
    pop ix
    ret
```

### Группы раскладок

В `layout { … }` можно задать размеры сразу нескольких структур ASM.
После размера можно перечислить типы нужных EXX полей. Смещения по-прежнему
берутся из ASM. В примере `address` — слово по смещению `EXTERNAL_CELL.address`.

```text
layout {
    EXTERNAL_CELL: 5 { address: u16 }
    DRAW_SURFACE: 3
}

HL read_address(cell: EXTERNAL_CELL → IY) { return cell->address }
```

```asm
read_address:
    ld l, (iy + EXTERNAL_CELL.address)
    ld h, (iy + EXTERNAL_CELL.address + 1)
    ret
```

### Группы полей

`field ИМЯ { … }` позволяет указать типы полей без повтора имени структуры.
Во внешнем блоке `field { … }` можно сочетать такие группы и отдельные
записи с точкой. Тип вложенной структуры нужен, чтобы перейти к её полю.
Записи в блоках можно разделять переносами строк, запятыми и точками с запятой.

```text
field {
    VID_SESSION { candidate: DRAW_SURFACE }
    DRAW_SURFACE.page0: u8
}

A read_page(session: VID_SESSION → IX) { return session->candidate.page0 }
```

```asm
read_page:
    ld a, (ix + VID_SESSION.candidate + DRAW_SURFACE.page0)
    ret
```

### Структуры EXX

`struct` размещает `u8`, `u16` с младшим байтом первым и другие типы
известного размера в порядке объявления без выравнивания. Структуру ASM
известного размера можно вложить как поле. В константных выражениях
`DRAW_SURFACE` означает размер структуры EXX, а `DRAW_SURFACE.page0` —
смещение поля.

```text
struct DRAW_SURFACE {
    mode: u8
    page0: u8
    page1: u8
}

A read_first_page(surface: DRAW_SURFACE → IX) { return surface->page0 }
```

Вывод для `sjasmplus`. В листинге опущены директивы защиты от повторного включения.

```asm
    STRUCT @DRAW_SURFACE
mode BYTE
page0 BYTE
page1 BYTE
    ENDS

read_first_page:
    ld a, (ix + 1)
    ret
```

`z80asm` генерирует `DEFVARS` для полей и `DEFC` для размера. В sjasmplus
в именах полей используется точка, а в z88dk-z80asm — подчёркивание.
Таргет `asm` использует числовые смещения в сгенерированных инструкциях.
См. [подключение структур в ASM](README.ru.md#подключение-структур-в-asm).

### Локальные имена регистров

Локальная привязка даёт имя регистру или сразу нескольким регистрам. Чтение по имени возвращает
текущее содержимое регистра.

```text
(cursor, remaining) → (HL, DE)
cursor += 1
```

```asm
    inc hl
```

### Проверка аргументов при вызове

EXX проверяет количество и расположение аргументов. В этом примере вызывающая процедура явно
переносит значение из D в требуемый E.

```text
extern select_page(page → E)
select_from_d(page → D) clobbers(E) {
    E = page
    select_page(E)
}
```

```asm
select_from_d:
    ld e, d
    call select_page
    ret
```

### Несколько возвращаемых значений

Значения возвращаются в порядке сигнатуры. Здесь CF сохраняет своё значение, а A получает 5.
Если для перестановки значений нужен временный регистр, пересылки указываются явно.

```text
(CF, A) status(carry → CF) { return (carry, 5) }
```

```asm
status:
    ld a, 5
    ret
```

### Возврат готовых значений в регистрах

`return` без выражения возвращает текущие значения регистров и флагов из
сигнатуры процедуры. EXX проверяет, что каждый объявленный результат определён
на всех путях к этому оператору. В примере оба результата передал вызывающий код.

```text
(CF, BC) relay(carry → CF, cursor → BC) { return }
```

```asm
relay:
    ret
```

### Возврат в конце процедуры

На закрывающей `}` процедура возвращает текущие значения объявленных выходных
регистров и флагов. EXX проверяет, что они определены на каждом пути к этой
скобке. Для досрочного выхода используйте `return`.

```text
A read_byte(byte → E) {
    A = byte
}
```

```asm
read_byte:
    ld a, e
    ret
```

### Получение результатов вызова

Перечислите все регистры результата в порядке объявления. Если результат не нужен, запишите
вызов отдельным оператором. Условный смысл результата, например код ошибки в A при CF=1, укажите
в описании процедуры.

```text
extern (A, HL, DE) query()
HL inspect() clobbers(A, DE) {
    (A, HL, DE) = query()
    return HL
}
```

```asm
inspect:
    call query
    ret
```

### Хвостовые вызовы

Возврат вызова с совместимыми выходными регистрами превращается в переход. Целевая процедура
должна быть доступна при текущем отображении памяти.

```text
extern A read_byte()
A fetch() { return read_byte() }
```

```asm
fetch:
    jp read_byte
```

### Условные вызовы

Если в ветке только вызов процедуры, EXX может сгенерировать условный
`call`. Результаты и `clobbers` действуют на пути, где вызов выполняется.

```text
extern update()
refresh(ready → Z) { if (ready) update() }
```

```asm
refresh:
    call z, update
    ret
```

### Условные хвостовые вызовы

Если состояние регистров и стека позволяет сразу передать управление,
EXX может свернуть хвостовой вызов в условный переход. Для ближней процедуры
в том же модуле возможен `jr` по обычным правилам выбора перехода.

```text
extern A read_byte()
A fetch(ready → Z) {
    if (ready) return read_byte()
    return 0
}
```

```asm
fetch:
    jp z, read_byte
    ld a, 0
    ret
```

### Объявление изменяемых регистров

`clobbers` разрешает изменения, видимые вызывающему коду. Объявленный результат доступен и
тогда, когда его регистр входит в `clobbers`. F охватывает шесть документированных флагов. Пары
AF, BC, DE и HL перекрываются со своими частями.

```text
extern (CF, A) probe() clobbers(HL, F)
```

Само объявление `extern` не порождает инструкций. При вызове `probe` из модуля для `z80asm` в его заголовке появится `EXTERN probe`.

### Подключение объявлений ABI

Пишите `use "путь.abi"` на уровне файла EXX или ABI. Относительный путь
считается от каталога файла с `use`. Один ABI-файл загружается один раз,
даже если он доступен по нескольким путям или также передан через `--abi`.
Циклические подключения и конфликтующие объявления приводят к ошибке.

```text
// abi/video.abi
extern A read_page(page → E)
```

```text
// caller.exx
use "abi/video.abi"
A fetch_page(page → E) { return read_page(page) }
```

```asm
fetch_page:
    jp read_page
```

В блоке `use` разделяйте пути переводами строк, запятыми или точками с
запятой.

```text
use {
    "abi/video.abi"
    "abi/console.abi"
}
```

ABI-файл может содержать объявления процедур и данных через `extern`, а
также `struct`, `layout`, `field`, `const` и `use`. Реализация подключается
на этапе ассемблирования или линковки. Сам `use` не выводит директиву `INCLUDE`.

### Проверка доступности значений

Для чтения регистр должен содержать определённое значение на каждом пути, в том числе после
перехода на новую итерацию. Здесь после `work()` нужно заново определить D, прежде чем вернуть
DE.

```text
extern work() clobbers(D)
DE reset_high(word → DE) {
    work()
    D = 0
    return word
}
```

```asm
reset_high:
    call work
    ld d, 0
    ret
```

## Условия и циклы

### Проверка флагов

`if (CF)` и `if (Z)` читают текущий флаг. Сразу после вызова такая проверка использует флаг,
который вернула процедура.

```text
(CF, A) = probe()
if (CF) return (CF, A)
return (0, 1)
```

```asm
    call probe
    ret c
    xor a
    inc a
    ret
```

### Проверка аккумулятора

`if (A)` проверяет, что байт ненулевой, а `if (!A)` — что он равен нулю. В обоих случаях
выполняется `or a`, которая обновляет F.

```text
if (!A) return A
return 1
```

```asm
    or a
    ret z
    ld a, 1
    ret
```

### Беззнаковые сравнения

При сравнении двух байтов один операнд должен находиться в A. Ветка `else` выполняется, если
условие ложно. Сравнение обновляет флаги.

```text
if (A < C) return A
else return C
```

```asm
    cp c
    ret c
    ld a, c
    ret
```

### Присваивание в условии

Заключите присваивание в скобки, чтобы загрузить значение непосредственно в месте проверки.
Регистр назначения можно указать через алиас.

```text
if ((A = session->action) == RST8_VID_PREP_DRAW) return 1
return 0
```

```asm
    ld a, (ix + VID_SESSION.action)
    cp RST8_VID_PREP_DRAW
    jr nz, exx__example_1
    ld a, 1
    ret
exx__example_1:
    ld a, 0
    ret
```

### Сокращённое вычисление условий

`&&` и `||` вычисляют правую часть только при необходимости. Здесь поле загружается в A только
на пути с установленным Z.

```text
if (Z && (A = session->action) == 1) return A
return 0
```

```asm
    jr nz, exx__example_1
    ld a, (ix + VID_SESSION.action)
    cp 1
    ret z
exx__example_1:
    ld a, 0
    ret
```

### Условное ветвление

`if` выполняет тело при истинном условии. В примере процедура возвращает 1
при установленном Z. При сброшенном Z выполняется оператор после тела.

```text
A choose(flag → Z) {
    if (flag) return 1
    return 2
}
```

```asm
choose:
    jr nz, exx__choose_1
    ld a, 1
    ret
exx__choose_1:
    ld a, 2
    ret
```

### Цикл с предусловием

`while` проверяет условие до каждой итерации. При нуле в A этот цикл сразу заканчивается.

```text
while (A) {
    HL += 1
    A -= 1
}
```

```asm
exx__example_1:
    or a
    jr z, exx__example_2
    inc hl
    sub 1
    jr exx__example_1
exx__example_2:
```

### Цикл с постусловием

`do { … } while (условие)` выполняет тело один раз перед первой проверкой.
Условие может читать флаги, установленные в конце тела. В примере каждая
итерация выводит пробел и проверяет, дошёл ли курсор до позиции табуляции.

```text
extern data __console_x: u8
extern put_cell(character → A) clobbers(AF, BC, DE, HL)

tab() clobbers(AF, BC, DE, HL) {
    do {
        A = 0x20
        put_cell(A)
        A = __console_x
        A &= 7
    } while (!Z)
}
```

```asm
tab:
exx__tab_1:
    ld a, 32
    call put_cell
    ld a, (__console_x)
    and 7
    jr nz, exx__tab_1
    ret
```

### Счётный цикл

`repeat` выполняет тело, затем уменьшает B командой `djnz`, которая сохраняет флаги. При
начальном нуле будет 256 итераций, если тело сохраняет B. Если начало цикла слишком далеко
или расстояние неизвестно, `djnz` переходит на соседнюю команду `jp`, которая возвращает
управление в начало цикла. Когда B достигает нуля, короткий `jr` пропускает этот `jp`.

```text
count → B
count = 16
repeat (count) {
    *HL = A
    HL += 1
}
```

```asm
    ld b, 16
exx__example_1:
    ld (hl), a
    inc hl
    djnz exx__example_1
```

### Досрочный выход из цикла

`break` выходит из ближайшего цикла. Здесь при нулевом байте выход происходит до
изменения HL и B.

```text
repeat (B) {
    if (!(A = *HL)) break
    HL += 1
}
```

```asm
exx__example_1:
    ld a, (hl)
    or a
    jr z, exx__example_2
    inc hl
    djnz exx__example_1
exx__example_2:
```

### Локальные метки и goto

Используйте метку и `goto` для общего выхода или обратного перехода.
Перейти можно в своём блоке или во внешний блок в пределах одной процедуры.
При выходе из `keep` EXX восстанавливает сохранённые пары. В точке назначения
он проверяет доступность регистров и состояние стека.

Таргет `sjasmplus` выводит локальные метки вроде `.exx__1`, а `z80asm` —
`@exx__1`. Общий таргет `asm` и процедуры с блоком `asm` используют уникальные
имена вроде `exx__fallback_1`. Метка внутри вставки ASM может изменить область
видимости локальных меток ассемблера.

```text
A fallback(ready → Z) {
    if (!ready) goto failed
    return 1
failed:
    return 0
}
```

```asm
fallback:
    jr nz, exx__fallback_1
    ld a, 1
    ret
exx__fallback_1:
    ld a, 0
    ret
```

## Память и символы

### Байтовые указатели

`*ptr` обращается к байту по адресу в BC, DE, HL, IX или IY. При адресации через BC или DE байт
передаётся через A. Здесь получаются `ld a,(de)` и `ld (hl),a`.

```text
(src, dst) → (DE, HL)
A = *src
*dst = A
```

```asm
    ld a, (de)
    ld (hl), a
```

### Индексная адресация

Для указателя в IX или IY допустимо постоянное смещение от −128 до 127. Символьное смещение
вычисляет основной ассемблер.

```text
A previous(cursor → IX) { return cursor[-1] }
```

```asm
previous:
    ld a, (ix - 1)
    ret
```

### Типизированные поля структур

Имя раскладки задаёт префикс смещений и проверяется при передаче указателя по имени, через алиас
или физический регистр. Для загрузки байта ниже таргет `asm` использует `VID_CTX.config`, а
`z80asm` — `VID_CTX_config`. За адрес отвечает вызывающая сторона.

```text
A config(ctx: VID_CTX → IY) { return ctx->config }
```

```asm
config:
    ld a, (iy + VID_CTX.config)
    ret
```

### 16-битные поля

По умолчанию поле имеет ширину `u8`. При ширине `u16` EXX читает или пишет два байта, начиная с
младшего. Оба смещения должны попадать в диапазон индекса. Слово может находиться в BC, DE или
HL. Можно также записать константу.

```text
field DRV_HEADER.ops: u16
install(h: DRV_HEADER → IY, table → HL) { h->ops = table }
```

```asm
install:
    ld (iy + DRV_HEADER.ops), l
    ld (iy + DRV_HEADER.ops + 1), h
    ret
```

### Вложенные поля структур

Объявите вложенное поле с именем его раскладки и обращайтесь к его членам
через точку после первого поля. EXX складывает ассемблерные смещения
и берёт размер из типа конечного поля.

```text
field VID_SESSION.candidate: VID_SURFACE
field VID_SURFACE.mode: u16

set_mode(session: VID_SESSION → IX, mode → HL) {
    session->candidate.mode = mode
}
```

```asm
set_mode:
    ld (ix + VID_SESSION.candidate + VID_SURFACE.mode), l
    ld (ix + VID_SESSION.candidate + VID_SURFACE.mode + 1), h
    ret
```

### Адреса внешних данных

Объявите символ данных через `extern data` и возьмите его адрес оператором `&`. Таргет `z80asm`
добавит `EXTERN` для используемых данных.

```text
extern data bs_storage_ops
HL table_address() { return &bs_storage_ops }
```

```asm
table_address:
    ld hl, bs_storage_ops
    ret
```

### Определение статических данных

На уровне файла `data` определяет байт или слово с начальным значением.
Значение задаётся константным выражением. Для слова можно указать адрес
других данных. Определение выводится в исходном порядке в выбранной секции.
`name` обозначает значение в памяти, а `&name` — его адрес.

```text
data cursor: u16 = 0x4000
HL load_cursor() { return cursor }
```

```asm
cursor:
    defw 16384

load_cursor:
    ld hl, (cursor)
    ret
```

### Типизированные внешние данные

Укажите размер символа из другого модуля, чтобы читать или записывать его
содержимое. На Z80 байт по абсолютному адресу читается и пишется через A,
а слово — через подходящую регистровую пару.

```text
extern data status: u8
set_status(value → A) { status = value }
```

```asm
set_status:
    ld (status), a
    ret
```

### Константы ассемблера

Имена в верхнем регистре и квалифицированные имена смещений передаются в ASM как символы. Их
значения и адреса банков задаёт основной проект.

```text
A = VID_CTX.slot0 ^ VID_CTX.slot1
```

```asm
    ld a, 0 + (VID_CTX.slot0 ^ VID_CTX.slot1)
```

### Константы EXX

`const ИМЯ = выражение` объявляет одну константу. В блоке `const { … }`
можно объявить несколько. Выражения могут использовать целочисленную
арифметику, другие константы, размеры и смещения полей структур.
Объявления из переводимого файла выводятся как `EQU` или `DEFC`.

```text
const {
    SCREEN = 0x4000
    ATTRIBUTES = SCREEN + 0x1800
}
```

```asm
SCREEN EQU 16384
ATTRIBUTES EQU 22528
```

### Адрес размещения

`origin выражение` выводит `ORG` в соответствующем месте. Действуют
правила размещения выбранного ассемблера. z88dk-z80asm может создать
отдельный бинарный файл для секции с явно заданным адресом.

```text
origin 0x8000
data marker: u8 = 42
```

```asm
    ORG 32768
marker:
    defb 42
```

## Арифметика и биты

### Числовые литералы

Доступны десятичная, шестнадцатеричная и двоичная записи. Оба присваивания загружают 128.

```text
A = 0x80
B = 0b10000000
```

```asm
    ld a, 128
    ld b, 128
```

### Арифметика с аккумулятором

Укажите регистр назначения явно. EXX загрузит левый операнд в A перед
сложением с C. Загрузка должна сохранить правый операнд.

```text
A = B + C
```

```asm
    ld a, b
    add a, c
```

### Префиксный инкремент

`++reg` увеличивает регистр или его алиас на месте и выдаёт новое значение.
Оператор можно использовать отдельно, в присваивании или в условии. Результат
циклически переполняется по разрядности регистра. Байтовый `inc` обновляет
остальные арифметические флаги и сохраняет CF. `inc` регистровой пары сохраняет
все флаги.

```text
if ((A = ++column) < columns) return (CF, cursor)
```

```asm
    inc c
    ld a, c
    cp e
    ret c
```

Здесь `column` находится в C, `columns` в E, `cursor` в BC. Возвращаемый CF
устанавливает `cp e`.

### Префиксный декремент

`--reg` уменьшает регистр или его алиас на месте и выдаёт новое значение.
Байтовый `dec` сохраняет CF. `dec` регистровой пары сохраняет все флаги.

```text
HL shorten(remaining → HL) {
    --remaining
    return remaining
}
```

```asm
shorten:
    dec hl
    ret
```

### Постфиксный инкремент

`reg++` увеличивает регистр. Чтобы использовать исходное значение, присвойте
его другому регистру той же разрядности. Такое присваивание можно заключить
в скобки и использовать в условии.

```text
if ((A = column++) < columns) return (CF, cursor)
```

```asm
    ld a, c
    inc c
    cp e
    ret c
```

### Постфиксный декремент

`reg--` уменьшает регистр. Отдельная команда отбрасывает исходное значение.
При присваивании оно копируется в другой регистр перед уменьшением.

```text
(A, B) take_count(count → B) clobbers(F) {
    A = count--
    return (A, count)
}
```

```asm
take_count:
    ld a, b
    dec b
    ret
```

### Присваивание в арифметике

Присваивание в скобках записывает значение в явно указанный регистр и
использует этот регистр как операнд. EXX вычисляет операнды слева направо
и проверяет, что вложенная запись сохраняет нужное значение или адрес.

```text
IY adjust(base → IY) clobbers(DE, CF, HF, N) {
    base += (DE = BS_WORKSPACE_OFF + RST8_DATA_OFF)
    return base
}
```

```asm
adjust:
    ld de, 0 + (BS_WORKSPACE_OFF + RST8_DATA_OFF)
    add iy, de
    ret
```

### Арифметика регистровых пар

Указатель можно увеличить или уменьшить непосредственно в регистровой паре. Сложение `HL += DE`
даёт `add hl,de`.

```text
HL += DE
HL -= 1
```

```asm
    add hl, de
    dec hl
```

### Копирование регистровых пар

Копирование между BC, DE и HL использует две байтовые загрузки и сохраняет флаги.

```text
HL copy_pair(src → BC) { return src }
```

```asm
copy_pair:
    ld h, b
    ld l, c
    ret
```

### Вычитание регистровых пар

При вычитании BC, DE или HL из HL EXX сбрасывает перенос и выполняет `sbc`.
Последовательность сохраняет A и выставляет флаги по результату вычитания.

```text
HL remaining(size → HL, skip → DE) clobbers(F) {
    size -= skip
    return size
}
```

```asm
remaining:
    or a
    sbc hl, de
    ret
```

### Проверка регистровой пары на ноль

Объедините байты пары операцией OR в присваивании в A. Условие использует
флаги этого OR.

```text
A has_size(size → BC) clobbers(F) {
    if ((A = B | C)) return 1
    return 0
}
```

```asm
has_size:
    ld a, b
    or c
    jr z, exx__has_size_1
    ld a, 1
    ret
exx__has_size_1:
    ld a, 0
    ret
```

### Проверка бита

`$` выбирает бит с постоянным номером от 0 до 7. Проверка регистра или индексного поля
использует `bit` и сохраняет CF.

```text
if (packet->status$3) return 1
return 0
```

```asm
    bit 3, (iy + PACKET.status)
    jr z, exx__example_1
    ld a, 1
    ret
exx__example_1:
    ld a, 0
    ret
```

### Запись бита

Присваивание `true` даёт `set`, а `false` — `res`. Обе команды сохраняют F.

```text
packet->status$3 = false
```

```asm
    res 3, (iy + PACKET.status)
```

### Маска AND

`&=` оставляет в A биты, заданные маской. Этот пример даёт `and 127` и обновляет F.

```text
A &= ~(1 << 7)
```

```asm
    and 127
```

### Маска OR

`|=` устанавливает в A указанные маской биты. Здесь получится `or 128` с обновлением F.

```text
A |= 0x80
```

```asm
    or 128
```

### Исключающее ИЛИ

`^=` инвертирует биты по маске. Для операнда в E получится `xor e` с обновлением F.

```text
A ^= E
```

```asm
    xor e
```

### Инверсия байта

`~A` инвертирует все восемь битов командой `cpl`. CF, S, Z и PV сохраняются.

```text
A = ~A
```

```asm
    cpl
```

### Логические сдвиги байта

`<<=` сдвигает влево, а `>>=` — вправо с заполнением нулями. Байтовые сдвиги и вращения
принимают регистр или индексное поле и число шагов от 0 до 255, известное EXX. Каждый шаг
обновляет F. При нуле шагов значение и флаги сохраняются.

```text
B >>= 2
```

```asm
    srl b
    srl b
```

### Арифметический сдвиг вправо

`sra` на каждом шаге заполняет старший бит знаковым. Именованные операции сдвига
и вращения по умолчанию выполняют один шаг.

```text
sra(D, 2)
```

```asm
    sra d
    sra d
```

### Сдвиг слова влево

Сдвиг HL влево на один разряд даёт `add hl,hl`. Команда обновляет CF, HF и N и сохраняет
остальные документированные флаги.

```text
HL <<= 1
```

```asm
    add hl, hl
```

### Циклические вращения

`rlc` вращает байт влево, а `rrc` — вправо. Вытесненный бит попадает на другой конец
байта и одновременно копируется в CF.

```text
rlc(B)
```

```asm
    rlc b
```

### Вращения через перенос

`rl` и `rr` используют CF как дополнительный бит. В этом примере
`sra d` помещает младший бит D в CF, затем `rr e` переносит его в старший бит E.

```text
sra(D)
rr(E)
```

```asm
    sra d
    rr e
```

### Сложение с переносом

`adc` прибавляет к первому операнду второй и входной CF, затем обновляет F. На Z80
доступны формы с A и HL.

```text
adc(HL, DE)
```

```asm
    adc hl, de
```

### Вычитание с заёмом

`sbc` вычитает из первого операнда второй и входной CF, затем обновляет F. Здесь
получится `sbc a,e`.

```text
sbc(A, E)
```

```asm
    sbc a, e
```

## Стек и наборы регистров

### Сохранение регистров на время блока

`keep` сохраняет регистровые пары в порядке перечисления и восстанавливает их в обратном порядке.
Пары можно называть через алиасы. Здесь копирование сохраняет оба указателя, счётчик и AF, занимая восемь байт стека.

```text
copy_bytes(source → HL, destination → DE, count → BC) {
    keep(AF, source, destination, count) {
        ldir(destination, source, count)
    }
}
```

```asm
copy_bytes:
    push af
    push hl
    push de
    push bc
    ldir
    pop bc
    pop de
    pop hl
    pop af
    ret
```

Вложенные блоки восстанавливают регистры начиная с внутреннего. При раннем `return` закрываются все
активные блоки `keep`, а при `break` — только те, из которых выходит переход. Условие проверяется по флагам
до восстановления. Если EXX не может доказать, что восстановление сохранит живой результат или аргумент
хвостового вызова, он укажет на ошибку. Например, чтобы вернуть новое значение A, запишите `return 5`
после `keep(AF)`. Ручные операции со стеком внутри блока должны быть сбалансированы над сохранёнными словами.

### Сохранение в стеке

`push` сохраняет слово, а `pop` загружает его в выбранную пару. EXX отслеживает
инициализированные части слова и после вызова. Здесь процедура сохраняет BC по своему ABI. На
слиянии веток глубина стека должна совпадать, при любом выходе, включая хвостовой переход, —
равняться входной. SP зарезервирован для стека вызовов. При записи через указатели следите за
сохранностью слов на стеке.

```text
extern work() clobbers(BC)
run_preserving_bc() {
    push(BC)
    work()
    pop(BC)
}
```

```asm
run_preserving_bc:
    push bc
    call work
    pop bc
    ret
```

### Обмен регистровых пар

Обмен DE и HL выполняется одной командой. Записи `ex(DE, HL)` и `ex(HL, DE)` дают одинаковый код.

```text
ex(DE, HL)
```

```asm
    ex de, hl
```

### Обмен с вершиной стека

`ex_sp` обменивает HL, IX или IY со словом на вершине стека. Здесь IX получает прежнее
значение BC, затем DE получает прежнее значение IX.

```text
push(BC)
ex_sp(IX)
pop(DE)
```

```asm
    push bc
    ex (sp), ix
    pop de
```

### Теневые регистры

`ex(AF)` даёт `ex af,af'`. Вызов `exx()` обменивает BC, DE и HL с их теневыми парами. В сигнатуре
теневые пары обозначаются `AF_ALT`, `BC_ALT`, `DE_ALT` и `HL_ALT`. Пример записывает значение в
теневой HL и восстанавливает активный набор.

```text
set_alt_pointer(pointer → HL) clobbers(HL_ALT) {
    push(pointer)
    exx()
    pop(HL)
    exx()
}
```

```asm
set_alt_pointer:
    push hl
    exx
    pop hl
    exx
    ret
```

## Порты и блочные операции

### Чтение порта

Для `in(BC)` вся пара BC задаёт адрес порта. Чтение обновляет флаги и сохраняет CF. В форме
`A = in(0xFE)` старший байт адреса берётся из A до чтения, F сохраняется.

```text
D = in(BC)
```

```asm
    in d, (c)
```

### Запись в порт

`out(BC, E)` записывает E по полному адресу BC. В примере с непосредственным портом A
задаёт и старший байт адреса, и записываемое значение. Обе формы сохраняют F.

```text
out(0xFE, A)
```

```asm
    out (254), a
```

### Блочное копирование

`ldir()` копирует из HL в DE со счётчиком BC. При начальном нуле копируются 65 536 байт.
Направление и повторение задаются выбором `ldi`, `ldir`, `ldd` или `lddr`.
Любая блочная операция принимает либо пустые скобки, либо полный список регистров.
Обе формы читают и меняют одни и те же регистры и флаги. В полной форме EXX проверяет
порядок алиасов. При привязках ниже запись `ldir(src, dst, count)` даст ошибку компиляции.

```text
(dst, src, count) → (DE, HL, BC)
ldir(dst, src, count)
```

```asm
    ldir
```

### Блочный поиск

`cpir()` сравнивает A с байтами начиная с адреса HL до совпадения или исчерпания BC.
Семейство поиска включает `cpi`, `cpir`, `cpd` и `cpdr`.

```text
cpir(HL, A, BC)
```

```asm
    cpir
```

### Блочный ввод

`inir()` заполняет память начиная с адреса HL. C задаёт младший байт адреса порта,
а B задаёт старший байт и служит счётчиком. Семейство ввода включает `ini`, `inir`, `ind` и `indr`.
После блочного ввода или вывода анализатор
разрешает читать Z и считает остальные флаги перезаписанными.

```text
inir(HL, C, B)
```

```asm
    inir
```

### Блочный вывод

`otir()` передаёт в порт байты начиная с HL. При каждой передаче HL увеличивается,
а B уменьшается. Семейство вывода включает `outi`, `otir`, `outd` и `otdr`.

```text
otir(C, HL, B)
```

```asm
    otir
```

## Вставки ASM

### Ассемблер на уровне файла

Блок `asm { … }` позволяет размещать таблицы, метки, макросы и директивы между процедурами
EXX. Все таргеты выводят блоки в исходном порядке после заголовка модуля. Отступы, имена
символов и комментарии внутри блока передаются ассемблеру в исходном написании. Для условной
сборки используйте синтаксис выбранного ассемблера. Собственного препроцессора
`#define` и `#ifdef` у EXX нет.

```text
asm {
hex_digits:
    defb "0123456789ABCDEF"
}
```

```asm
hex_digits:
    defb "0123456789ABCDEF"
```

### Встроенный ассемблер с регистровым контрактом

Внутри процедуры в скобках указываются читаемые регистры, после стрелки — результаты,
в `clobbers` — остальные изменяемые регистры и флаги. В контракте допустимы алиасы,
в ассемблерном тексте используются физические имена регистров. Пропущенный список
считается пустым. Например, `asm { nop }` сохраняет все регистры и флаги. EXX проверяет
окружающий код по объявленному контракту. Автор вставки отвечает за его соблюдение,
восстановление стека и переход управления к следующему оператору EXX. Внешние символы,
которые используются только внутри вставки, объявляются директивами ассемблера.

```text
A invert(value → A) clobbers(HF, N) {
    asm(value) → A clobbers(HF, N) {
        cpl
    }
    return value
}
```

```asm
invert:
        cpl
    ret
```
